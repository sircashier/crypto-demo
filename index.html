1 · Hash playground

SHA-256

SHA-256

What’s happening

A hash function turns any input into a fixed-size fingerprint: 256 bits, shown as 64 hex characters.

  • Same input, same hash. Always.
  • Avalanche effect. Change one letter and about half of the 256 bits flip (roughly 128). Characters that differ are highlighted.
  • Any length in, same size out. Try one letter, then paste a whole paragraph.

Why it matters

Comparing two short hashes tells you whether two big files are identical, which is how a published checksum protects a download. But a hash can’t tell you who published it. That is what demo 3 fixes.

What’s happening

The program hashes random messages, remembers every hash it has seen, and stops when two different messages share one.

  • Any collision: about 2n/2 tries (the birthday paradox: every message is compared against all earlier ones).
  • Match one given message: about 2n tries, since each try has a single chance in 2n of hitting.

Run both at the same size and compare the counts. Your numbers will differ from your neighbour’s, since the messages are random. “Around” is the right word.

Why it matters

Real SHA-256 has n = 256, so a collision needs about 2128 tries. No computer on Earth gets there.

What’s happening

  • Sign: the message is hashed, and the private key turns that hash into a signature. (ECDSA, P-256 curve.)
  • Verify: anyone with the public key can check that signature against the message.

Try these

  • Change ₱100 to ₱999 and keep the signature: invalid (integrity).
  • Forge a signature with your own key: invalid for Eunice. It only verifies under the forger’s key, so only Eunice’s private key could have produced a signature her public key accepts (authentication).

Why it matters

A hash told us whether the data changed. A signature also tells us who signed it, and because only she holds the key, she can’t easily deny it (non-repudiation).
